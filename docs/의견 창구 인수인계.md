# 의견 창구 인수인계 — 담당자가 바뀌어도 돌아가게

앱 오른쪽 아래 「의견 보내기」는 두 길로 움직입니다. **길 1이 막혀도 길 2는 항상 됩니다.** 외부 서비스는 쓰지 않습니다 — 전부 GitHub 안입니다.

| 길 | 무엇 | 필요한 것 |
|---|---|---|
| 1. 온라인 | 앱 → (공개 토큰) → 비공개 접수 저장소의 워크플로 → **GitHub 이슈** 자동 생성, 캡처는 댓글로 | 아래 「처음 켜기」 |
| 2. 파일 | 길 1이 없거나 실패하면 제보문+캡처를 HTML 파일 하나로 내려줌. 사용자가 메신저·메일로 보냄 | 없음 |

## 원리 — 왜 계정 없는 사람이 보낼 수 있나

- 앱에는 **「워크플로 실행」 권한만 있는 토큰**이 들어 있습니다(공개된 것으로 칩니다). 이 토큰으로는 이슈를 읽거나 코드를 고칠 수 없고, 접수 저장소의 워크플로 하나를 켤 수만 있습니다.
- 워크플로는 **저장소 자체 권한**으로 이슈를 만들고 캡처를 커밋합니다. 그래서 진짜 열쇠는 밖으로 나가지 않습니다.
- 대가: 토큰이 공개라 누구나 워크플로를 돌릴 수 있습니다(= 스팸 가능). 남용이 보이면 토큰을 회수하고 다시 만들면 됩니다(1분).
- 한 번에 보낼 수 있는 양이 64KB라 캡처는 장당 따로 보냅니다. 이슈가 생기기까지 20~40초 걸립니다.

## 어디에 무엇이 사나

- 접수 워크플로: `feedback-inbox/.github/workflows/intake.yml` — **이 저장소에는 서식만** 있고, 실제로는 접수 저장소에 복사해 둡니다.
- 앱 쪽 설정: `src/ui/feedback/config.ts` (접수 저장소 이름) + Pages 배포 워크플로가 빌드할 때 넣는 공개 토큰(저장소 Secret `FEEDBACK_DISPATCH_TOKEN`).
- 이슈·캡처가 모이는 곳: 접수 저장소(기본 `2026-gne-dev-task-force-team/school-shiftgrid-feedback`, **비공개**). 캡처에 교사 실명이 보일 수 있으니 비공개여야 합니다.

## 처음 켜기 (또는 후임이 이어받기) — 15분

1. **접수 저장소**: 조직에 비공개 저장소 `school-shiftgrid-feedback`을 만들고, 이 저장소의 `feedback-inbox/` 안 내용을 그대로 올립니다(`.github/workflows/intake.yml`). Settings → Actions → General에서 Workflow permissions를 **Read and write**로 둡니다.
2. **봇 계정**(권장): 사람이 떠나도 살도록 조직용 GitHub 계정 `shiftgrid-bot`을 만들고(조직 공용 메일), 접수 저장소의 협력자로 넣습니다(권한 Write). 급하면 관리자 본인 계정으로 해도 되지만, 그 사람이 조직을 떠나면 토큰이 죽습니다.
3. **공개 토큰**: 봇 계정 → Settings → Developer settings → Fine-grained tokens → 새 토큰
   - Repository access: `school-shiftgrid-feedback` 하나만
   - Permissions: **Actions: Read and write** (그 외 없음 — Metadata는 자동)
   - 만료 1년. 만료·남용 시 이 절차로 다시 만들어 4번만 갈아 끼웁니다.
4. **앱 저장소 Secret**: 이 저장소 → Settings → Secrets and variables → Actions → `FEEDBACK_DISPATCH_TOKEN` 에 그 토큰. Pages 배포가 다시 돌면(아무 커밋이나 Actions 「Run workflow」) 앱에 들어갑니다.
5. 확인: 앱에서 시험 제보 하나(캡처 1장 포함) → 접수 저장소 Actions에 실행 2건, 이슈 1건 + 댓글 1건.

## 끄기·바꾸기

- 온라인 길만 끄려면 Secret `FEEDBACK_DISPATCH_TOKEN`을 지우고 배포를 한 번 돌립니다. 앱은 곧바로 길 2로 갑니다.
- 접수 저장소를 바꾸려면 `src/ui/feedback/config.ts`의 `FEEDBACK_REPO`와 토큰의 저장소 범위를 함께 바꿉니다.
- 스팸이 오면: 토큰 회수 → 새 토큰 → Secret 교체 → 배포. 이미 만들어진 스팸 이슈는 닫습니다.

## 왜 이렇게 만들었나

- 선생님들은 GitHub 계정이 없습니다. 계정 없이 이슈를 만들려면 어딘가에 열쇠를 든 코드가 돌아야 하는데, 외부 서비스(Cloudflare 등)를 두면 그 계정에 매달립니다. GitHub Actions를 그 자리로 쓰면 전부 조직 소유가 됩니다.
- 앱에 넣는 토큰은 「워크플로 켜기」만 되는 것이라 새도 읽히는 게 없습니다.
- 워크플로가 죽어도 창구가 죽지 않도록 파일 내려받기 길을 항상 남겼습니다.
